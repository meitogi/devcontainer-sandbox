# =============================================================================
# Base-image allowlist — the universal sandbox minimum
# =============================================================================
# Shipped at /etc/devcontainer-firewall/domains.d/00-base.txt by the base
# image. This is layer 1 of the 3-level model :
#   1. this file            — base image, always present, sufficient alone
#   2. project firewall/    — committed overlay (domains.txt, domains.d/,
#                             policy.d/), additive
#   3. project *.local.*    — gitignored personal overrides
#
# A project can OVERRIDE any host below from its committed files :
#   !disable host.com                 # drop the base definition entirely
#   !disable host.com                 # …or drop it AND redeclare narrower —
#   [GET] host.com                    # non-disable entries in the file that
#     /my/scope/*                     # declares the !disable survive
#
# Scope rule for inclusion here : needed by the sandbox tooling itself
# (Claude Code, VS Code, the baked wtf CLI, TLS plumbing, the baked
# image itself). Anything project-specific lives in the project layer.
# Syntax reference : header of the project template's firewall/domains.txt.
# =============================================================================

# === GitHub source tarballs — generic, for the extension-patch hook ==========
# 45-ext-patches.sh fetches a pinned source tarball of whatever repository the
# operator names in EXT_PATCHES_REPO. The image ships no default and names no
# repository, so these paths are deliberately owner-agnostic: pinning them to
# one owner would publish, in a public artefact, the address of a private one.
# Read-only GET on the tarball endpoints and nothing else — no contents API,
# no git protocol, no write verb.
#
# ext-patches-update adds one question to that: WHICH refs exist, so a human
# can move from one pinned set to the next without going to look it up. Same
# owner-agnostic shape, same GET-only rule, two named paths — the latest
# release and the tag list.

# Both hosts are already resolved by the Anthropic block above, so nothing is
# added here: a domains.txt path only supports a TRAILING `*`
# (_path_to_endpoint_regex), and `/repos/<owner>/<repo>/tarball/` needs two
# wildcards mid-path. Writing `/repos/*` instead would open every repository
# API for every owner. The exact shapes live in policy.d/ as real regexes:
#   policy.d/api.github.com.yaml   ^/repos/[\w.-]+/[\w.-]+/tarball/.+$
#   policy.d/api.github.com.yaml   ^/repos/[\w.-]+/[\w.-]+/(releases/latest|tags)$
#   policy.d/codeload.github.com.yaml   ^/[\w.-]+/[\w.-]+/legacy\.tar\.gz/.+$

# === CRL / OCSP — TLS certificate revocation infrastructure =================
# TLS chain validation by VS Code / curl / Node / browsers hits these
# endpoints to check whether a presented certificate has been revoked.
# Bodies are signed binary lists (DER-encoded), GET-only, low exfil risk.
# Without these, strict mode generates dozens of host_not_in_policy
# blocks per minute on perfectly normal TLS handshakes.

[GET] crl3.digicert.com                # DigiCert CRL distribution point
[GET] ocsp.digicert.com                # DigiCert OCSP responder
[GET] crl.microsoft.com                # Microsoft CRL distribution point
[GET] ocsp.msocsp.com                  # Microsoft OCSP responder

[GET] www.microsoft.com                # Microsoft PKI Operations — CRL distribution
  /pkiops/crl/*                        #   signed `.crl` binaries (Time-Stamp PCA etc.)
